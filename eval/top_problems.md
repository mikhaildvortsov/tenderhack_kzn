

## Топ-проблем движка

Данные из прогона на 749 кейсах (см. таблицы выше; движок менялся параллельно, цифры воспроизводятся командой запуска).
Особенность скоупа: 382 уникальных названия на 1 882 позиции, поэтому в synthetic ожидаемый набор `expected_codes_any` = все позиции с тем же названием, совместимые со всеми значениями; resolved почти недостижим (~4% кейсов).

1. **Название проигрывает характеристикам при выборе позиции (~73 из ~97 промахов top-1 — позиция с другим названием).**
   `Клещи, общая длина 253 мм, диэлектрические: Нет` -> top-1 «Обувь специальная диэлектрическая», `not_found`; `Головные уборы десткие, вид изделия: Бандана` -> «Головные уборы» вместо «Головные уборы детские»; `Стол компьютерный, ...` -> «Стол письменный»; `Стеллаж складской металлический` -> «Стеллаж офисный».
   Гипотеза: BM25 по документу name×3 + okpd2 + значения качественных характеристик даёт слишком большой вес словам из значений (диэлектрическ-), отсутствуют бонус за полное покрытие токенов названия и штраф за «лишние» слова названия кандидата; характеристика-несовпадение исключает точную позицию.
2. **`out_of_range` почти не детектируется (recall ~25%), а кейсы часто получают `resolved`/`ambiguous` без ошибки.**
   `Футболка трикотажная детская, рост 1940 см` -> resolved, issues=[]; `Сорочка ночная детская, рост 680 см` -> resolved; `Шапочка хирургическая ... диаметр 620 см` -> ambiguous без issue.
   Гипотеза: при отсутствии совместимых позиций по числовой характеристике штраф вместо исключения («отсутствующая характеристика — штраф») маскирует вне-диапазонное значение; проверка диапазона выполняется только у топ-позиции, а не по всем кандидатам с этим названием.
3. **Ложные `value_not_allowed` (error) на корректных данных: ~55 из 300 чистых кейсов (clean_no_false_error ~80%, цель SC-003 — FP ≤10%).**
   `... класс защиты одежды: 1 (водоотталкивающая)` -> движок создаёт характеристику «Вид защиты = водоотталкивающая [error]»; `Халат детский, тип ткани/трикотажного полотна: Смесовая` -> лишняя «Тип ткани = трикотажного [error]»; `Брюки ..., тип ткани/трикотажного полотна: Натуральная` -> «Вид ткани = Натуральная [error]».
   Гипотеза: значение в скобках и части составных названий («ткани/трикотажного полотна») разбираются как отдельные пары «характеристика-значение»; качественные значения сопоставляются с чужими характеристиками по общему слову.
4. **Опечатки в первом слове названия не исправляются (typo recall ~88%, но top-1 у typo 80%).**
   `тмба под школьную доску`, `прта, вид материала столешницы`, `Стол датский для дошкольных учреждений` (детский->датский: слово есть в словаре, исправление невозможно), `Сейф металический` (typo не помечен).
   Гипотеза: порог/длина для rapidfuzz (≥4 символов, 85) не покрывает слова 4-5 букв с удалением буквы; слова-валидные-словоформы (датский) не рассматриваются; опечатка в многословном названии не восстанавливается по контексту.
5. **Категория по «чужим» товарам и позиции вне КТРУ: 25 ошибок категории (tools -> clothing 17), в real_ste товары вне скоупа дают уверенную категорию.**
   `Набор отверток Wera 031551` -> clothing; `Молния Спираль юбочная ... замок-автомат` -> tools; `Шеврон "Герб ЦАО"` -> unknown; `Набор колёс-роликов для кресла BRABIX` -> clothing.
   Гипотеза: категория определяется лексическим пересечением с КТРУ без отрицательных признаков/порога уверенности; для товаров вне КТРУ (болгарки, перфораторы, шуруповёрты) корректный ответ — not_found/низкая уверенность. Ложных resolved на real_ste нет (real_false_resolved = 0, доля resolved ~1%).
6. **Рекомендации: у ~12% ambiguous нет ни одной рекомендации (SC-004 требует >=95%).** Особенно `incomplete` (9 из 45 без рекомендаций) и `synthetic_noisy`.
   Гипотеза: рекомендации строятся только по различающим характеристикам топ-N кандидатов; если кандидаты различаются лишь кодом/версией (идентичные характеристики), различающей характеристики нет и список пуст.
7. **Прочее.** `unit_mismatch`: precision ~76% (ложные срабатывания на корректных единицах, например «дюйм»); `unknown_characteristic` 10 FP на кейсах без такой ошибки; extraction precision ~47% — движок извлекает лишние характеристики из слов названия (`Вид=Перчатки`, `Назначение=Женский[suggested]`). Латентность не проблема: p95 ~6 мс (SC-005 выполнен с запасом).
