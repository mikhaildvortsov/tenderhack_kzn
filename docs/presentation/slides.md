# Презентация: автозаполнение характеристик СТЕ по КТРУ

Формат: 12 слайдов, ~7 минут (этап 2). Слайды с пометкой **[5 мин]** входят в 5-минутную версию (этап 1): 1, 2, 5, 6, 7, 8, 10, 11.

Цвета Портала: красный #db2b21, тёмный #1f2533, фон #f4f5f7. Файл: tenderhack_ktru.pptx.

## Слайд 1. Автозаполнение характеристик СТЕ по КТРУ [5 мин]

- Tender Hack · Казань · Портал поставщиков zakupki.mos.ru

**Спикер-ноты:** Добрый день. Мы сделали сервис, который по свободному описанию товара находит код КТРУ, заполняет характеристики и показывает ошибки с объяснением. Категории: одежда, мебель, инструменты.

## Слайд 2. Проблема: ручное заполнение СТЕ [5 мин]

- Поставщик вручную подбирает код из ~81 тыс. позиций КТРУ
- Характеристики: десятки полей, разные единицы (г/кг, мм/см)
- Опечатки и неверные значения - отклонение карточки, потеря времени
- Неясно, чего не хватает для однозначного кода
- ~81 тыс. - позиций КТРУ
- 3 - категории в v1
- 9 - типов ошибок

**Спикер-ноты:** Боль поставщика: огромный справочник, сложные характеристики, единицы измерения, опечатки. Ошибка в карточке - возврат и потеря времени. Нужен помощник, который объясняет, а не просто подставляет.

## Слайд 3. Цель и решение

- Свободный текст -> код КТРУ + унифицированные характеристики
- Пошаговое сужение кандидатов и конкретные подсказки
- Ошибки: где, какая, как исправить и почему
- Только открытые методы, CPU, миллисекунды, без LLM и платных API

**Спикер-ноты:** Цель - от текста к коду с объяснением. Ключевое решение: детерминированный конвейер без LLM на горячем пути - быстро, воспроизводимо, объяснимо.

## Слайд 4. Данные: КТРУ как источник истины

- Актуальный КТРУ (XML ЕИС), ~81 тыс. позиций; фильтр ACTIVE
- Скоуп: одежда, мебель, инструменты (~15-20 тыс.)
- Характеристики, допустимые значения и диапазоны, ОКЕИ
- xlsx-выгрузки СТЕ: синонимы и эталон для оценки; при расхождении приоритет КТРУ

**Спикер-ноты:** ETL разбирает XML в SQLite и собирает индекс. Выгрузки СТЕ используем как вспомогательные данные и для измерения качества.

## Слайд 5. Архитектура [5 мин]

- Изображение: docs/presentation/architecture.png
- Подпись: React SPA -> nginx -> stateless FastAPI-реплики -> read-only индекс в памяти; ETL офлайн

**Спикер-ноты:** Три блока: фронт на React, stateless бэкенд на FastAPI за nginx, офлайн ETL. Индекс read-only грузится в память - реплики масштабируются горизонтально. VRAM 0 ГБ.

## Слайд 6. Схема процесса (BPMN 2.0) [5 мин]

- Изображение: docs/bpmn/process.png
- Подпись: Дорожки: поставщик, веб-интерфейс, сервис анализа; отдельный пул ETL. Файл: docs/bpmn/process.bpmn

**Спикер-ноты:** Процесс от ввода до заполненной СТЕ. Развилки: код однозначен - показываем; иначе кандидаты и рекомендации с циклом уточнения; не найдено - подсказки исправления. Внизу ETL обновления КТРУ.

## Слайд 7. Алгоритм в 5 шагов [5 мин]

- 1. Нормализация: раскладка, опечатки, числа, единицы
- 2. Категория и кандидаты: BM25 + fuzzy, опц. e5-small
- 3. Извлечение: характеристики и приведение к ОКЕИ
- 4. Сужение: фильтр кандидатов, воронка
- 5. Валидация и подсказки: ошибки с обоснованием, информационный выигрыш

**Спикер-ноты:** Каждый шаг детерминирован и логируется в ответ: reason и confidence. Рекомендации выбирают характеристику, которая лучше всего делит оставшихся кандидатов.

## Слайд 8. Распознавание ошибок: 9 типов [5 мин]

- typo: «молотог» -> «молоток»
- layout: «vjkjnjr» -> «молоток»
- unit_mismatch: длина в кг
- value_not_allowed: значение вне списка КТРУ
- out_of_range: размер вне интервала
- missing_required: нет обязательной
- contradiction: два разных товара
- unknown_characteristic: нет в КТРУ
- category_mismatch: не наша категория
- Подпись: У каждой ошибки: фрагмент, тип, исправление, обоснование со ссылкой на КТРУ

**Спикер-ноты:** Девять типов ошибок. Для каждой показываем фрагмент в тексте, предлагаем замену и объясняем причину правилом справочника. Пользователь принимает или отклоняет.

## Слайд 11. Масштабируемость, скорость, ограничения [5 мин]

- **Скорость и масштаб**
- p95 <= 300 мс на CPU
- >= 50 RPS на реплику
- Stateless-реплики за nginx
- Read-only индекс, RAM <= 2 ГБ
- **Соответствие правилам**
- Linux, веб
- VRAM 0 ГБ (лимит 40 ГБ)
- Без проприетарных LLM и платных API
- Без low-code

**Спикер-ноты:** Нагрузка растёт - добавляем реплики. Без LLM нет GPU и очередей. Опциональный e5-small 118M параметров на CPU. Все ограничения хакатона соблюдены.
